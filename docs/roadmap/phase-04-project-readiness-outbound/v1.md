# Phase 4 — Project Readiness and Outbound Material

- Version: v1
- Status: Planned
- Depends on: Phase 3
- Blocks: Phase 5

## Objective

Prepare project material for departure, group selected lots into a controlled outbound batch, record pickup/departure evidence, and preserve an exact answer for what remains on the yard.

## Real-world workflow

1. Open a project and review active lots, quantities, locations, handling restrictions, verification age, and blocking issues.
2. Select full or partial lot quantities and create an outbound batch.
3. Move the batch from Planned to Ready after final review.
4. At pickup, confirm quantities, enter the operator name and optional carrier/driver reference, add proof photos, and record departure.
5. Review departed and remaining material separately; reverse an incorrect departure through an explicit correction event.

## Domain and public interfaces

- Add `OutboundBatch` and `OutboundLine` with project, site, state, selected lot/version, quantity, handling snapshot, actor, optional carrier/driver reference, proof photos, and timestamps.
- Use Planned, Ready, Departed, Cancelled, and Reversed outbound states.
- Derive readiness from active lots, verification state, and unresolved blocking issues while retaining project operational status separately.
- Partial departure splits lot quantity through the Phase 3 lineage model.
- Departure atomically updates lot presence/quantity, project summaries, outbound state, and activity.

## Data and services

- Add outbound planning, readiness, approval, departure, cancellation, reversal, and history ports.
- Lock selected quantities against concurrent movement or another active outbound batch.
- Store a handling and location snapshot on outbound lines so departure history remains meaningful after later changes.
- Reversal restores quantities through compensating records and never deletes the original departure.

## UI requirements

- Add `/inventory/outbound` and activate an Outbound navigation item.
- Add a readiness panel and Prepare Outbound action to project workspaces.
- Reuse lot tables/cards, quantity controls, handling warnings, photo evidence, operator fields, and activity patterns.
- Keep `/deliveries` outside Inventory and use cross-operational delivery terminology in its placeholder copy.

## Desktop behavior

- Provide project-grouped outbound queues, multi-lot selection, blocking-reason visibility, batch review, and departure history.
- Use tables for selected lots and remaining quantities with direct project/location links.

## Mobile behavior

- Focus on final quantity confirmation, handling warnings, proof photos, and the departure action.
- Use full-height review and sticky Ready/Record Departure controls with large touch targets.

## Migration and rollback

- Add outbound stores and readiness projections without changing prior movement history.
- Failed readiness or departure writes nothing and leaves reserved quantities unchanged.
- Rollback disables new planning while retaining readable outbound evidence and compensating reversals.

## Out of scope

Fleet-asset management, delivery scheduling, routing, installation, proof of installation, and carrier dispatch.

## Test plan

- Cover full/partial and multi-lot batches, blocked readiness, stale verification, duplicate reservations, departure, cancellation, reversal, and already-departed protection.
- Verify remaining quantities, presence, readiness, and activity after every transition.
- Add desktop/mobile Playwright and accessibility coverage for preparation and departure.

## Acceptance criteria

- Users can see exactly what is ready, blocked, selected, departed, and still on the yard.
- No lot quantity can be reserved or departed twice.
- Partial departure preserves lot lineage and remaining location.
- Every correction is auditable and fleet-asset concepts appear nowhere in the workflow.

## Final report requirements

Use the [shared final report](../README.md#shared-final-report), including reservation/concurrency results, remaining-quantity parity, reversal evidence, corrected Deliveries copy, and confirmation that Phase 5 was not started.

## Decision log

- v1: Outbound remains inside Inventory; it does not activate the broader Deliveries module.
- v1: Carrier/driver is optional evidence, not a managed fleet entity.
