# Phase 3 — Material Movement

- Version: v1
- Status: Planned
- Depends on: Phase 2
- Blocks: Phase 4

## Objective

Record complete, partial, and batch movement of material lots between valid storage positions without losing source history or changing total physical quantity.

## Real-world workflow

1. Start from a project, lot, storage location, or Movements workspace.
2. Select one or more active lots and choose full or partial quantities.
3. Choose a destination location and optional exact position.
4. Review handling restrictions, enter a reason, optional proof photo/note, and required operator name.
5. Confirm the movement and review the resulting lot locations and activity.

## Domain and public interfaces

- Add immutable `MaterialMovement` and `MovementLine` records with site, source, destination, quantity, reason, actor, timestamp, optional photo/note, and client mutation ID.
- Full movement updates the lot's current assignment while preserving the movement event.
- Partial movement creates a child lot and stores parent/root lineage.
- Batch movement accepts multiple lots but one destination; each line retains independent source and quantity history.
- Reject nonpositive or excessive quantities, identical source/destination, removed/outbound-completed lots, stale versions, and implicit cross-site moves.

## Data and services

- Add movement planning, validation, completion, and history ports with transactional local adapters.
- Enforce the invariant that total active plus removed/departed quantity does not change solely because of movement.
- Use optimistic UI only after local transaction validation; failures restore the prior view.

## UI requirements

- Add `/inventory/movements` and activate a Movements navigation item.
- Redirect `/inventory/material-movements` to the canonical route.
- Add Move Material actions to project, lot, and storage workspaces using the same movement form.
- Display handling requirements before destination confirmation.

## Desktop behavior

- Provide filters, movement history, multi-select, batch review, and source/destination comparison.
- Use tables for lot selection and movement history with clear drill-through links.

## Mobile behavior

- Use one-handed lot selection, searchable destinations, large quantity controls, camera capture, and a sticky Move Material action.
- Present exact-position selection as a touch-friendly grid and never depend on hover.

## Migration and rollback

- Add movement and lineage stores without changing historical receipt or verification records.
- A failed movement writes no lines and changes no lot assignment.
- Corrections use explicit reversal movements; rollback never deletes completed history.

## Out of scope

QR scanning, automated forklift processes, fleet-asset management, route scheduling, and inter-site logistics automation.

## Test plan

- Cover full, partial, multi-lot, and batch movement; source/destination validation; stale versions; lineage; reversal; and handling warnings.
- Prove total quantity invariance across movement and split operations.
- Test project, lot, and storage entry points plus desktop/mobile confirmation flows and accessibility.

## Acceptance criteria

- Every move records who, what, when, why, source, and destination.
- Partial moves create traceable child lots and retain the original lineage.
- Invalid and stale moves cannot alter inventory.
- All relevant project and storage views immediately show the new location.

Use the [shared final report](../README.md#shared-final-report), including quantity-invariance results, lineage examples, reversal results, and confirmation that Phase 4 was not started.
