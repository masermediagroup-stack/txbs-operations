# Phase 9 — Yard Map

- Version: v2
- Status: Planned with entry gate
- Supersedes for future implementation: `v1.md`
- Depends on: Phase 7 and a confirmed Site diagram/storage naming list

## Objective

Provide an accessible schematic entry point for confirmed Storage Locations without replacing the canonical Storage list and workspace.

## Current configuration

Lavon Yard currently has eight numbered Conex locations plus the confirmed North Yard, Middle Yard, and South Yard areas. Eight is configuration data, not a permanent domain constant. Richardson Office & Warehouse remains a separate Site with its own indoor warehouse and receiving area.

## Entry gate

- Obtain a user-confirmed diagram and naming list for the Site being mapped.
- Confirm operationally addressable areas, orientation, and adjacency.
- Never infer geometry, dimensions, capacity, or placement from older prompts or decorative references.
- Validate the current active Storage Location count immediately before implementation.

## Planned behavior

- Add versioned `SiteMapConfig` and `MapNode` records linked to existing Storage Location UUIDs.
- Build a data-driven accessible SVG with a synchronized list and no map-only actions.
- Derive counts from the same active Material Lots used by Storage pages.
- Desktop supports filters, hover/focus detail, project highlighting, Issue indicators, and Storage drill-through.
- Mobile defaults to the accessible list and offers an optional pan/zoom schematic.
- Hide the route when no valid confirmed configuration exists.

## Acceptance gate

- Every node references one active Storage Location.
- Map, list, and Storage counts match.
- All information and navigation work without the SVG.
- The displayed Conex count follows active Site configuration rather than a hard-coded value.

## Out of scope

GIS precision, GPS, live asset tracking, invented measurements, drag-and-drop administration, 3D Conex views, and capacity percentages without verified capacity data.
