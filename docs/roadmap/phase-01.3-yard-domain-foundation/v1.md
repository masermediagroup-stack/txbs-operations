# Phase 1.3 — Yard Domain Foundation

> **Historical version.** Preserved as immutable decision history. Current configuration has eight numbered Lavon Conex locations; see the roadmap index for the active contract.

- Version: v1
- Status: Planned
- Depends on: Current Inventory implementation
- Blocks: Phase 2

## Objective

Complete the missing yard-domain foundation so a user can find a project, inspect each physical material lot and its exact or general location, then add material, confirm its presence, update its location, or record an exception without inventing shipment workflows.

## Real-world workflow

1. Search by official project name, alias, handwritten field label, PO, job number, material, or location.
2. Open the matching project or inspect the answer directly in search results.
3. Review physical lots, package quantities, location precision, photos, condition, protection, accessibility, handling requirements, and last verification.
4. Add a material lot, confirm it is still present, record a changed location, mark it partially remaining/not found/removed, or create an issue.
5. Record the required operator name and append activity without deleting prior facts.

## Domain and public interfaces

- Add `Site`, `ProjectAlias`, `MaterialGroup`, `MaterialLot`, `StoragePosition`, `PhotoRecord`, `VerificationRecord`, `ActivityEvent`, and a minimal durable `Issue`.
- Use UUIDs for entity identifiers and UTC timestamps. Slugs remain route values only.
- Keep project operational status separate from lot presence, condition, protection, accessibility, and verification state.
- Model package type plus integer quantity at the lot. Project and material totals are derived.
- Support Box, Pallet, Crate, Framed Assembly, Wrapped Bundle, Appliance, Loose Item, Mixed Group, and Other with natural singular/plural labels.
- Support exact Conex 3×3 positions, general locations, and explicitly unknown positions.
- Compute `Needs Verification` when a present lot has not been confirmed for 14 days.
- Carry an `actorName` on every mutation and reserve nullable `actorUserId` for Phase 6.

## Data and services

- Introduce narrow project lookup, material-lot, verification, photo, activity, and issue ports driven by the workflows above.
- Implement versioned IndexedDB adapters with seed-on-first-run behavior and transactional use cases. UI code must not import storage APIs.
- Persist photo blobs separately from their metadata but within the same repository boundary.
- Provide a portable backup archive containing a versioned manifest, structured records, checksums, and media files; support validated import and backup round-trip tests.
- Migrate every current material group to one initial lot. Preserve existing quantities and locations, but set exact position, aliases, handling requirements, and verification evidence to unknown/empty rather than inventing values.
- Preserve the current seven Conex records and current project set.

## UI requirements

- Extend Project Finder, Project Workspace, Storage Workspace, Activity, and Issues rather than creating parallel V2 components.
- Explain alias and field-label matches in search results.
- Add reusable lot summaries, handling warnings, typed photo viewers, the Conex position selector, and action forms.
- Add Add Project Material, Confirm Still Here, Location Changed, Partially Remaining, Not Found, Removed from Yard, and Needs Review actions.
- Keep the current screen-reader page heading pattern and let the operational surface carry visible hierarchy.

## Desktop behavior

- Use dense tables for lots and verification queues with side panels or appropriately sized dialogs for focused actions.
- Keep project, location, and material drill-through links addressable through existing routes.
- Provide keyboard navigation for photo viewing and all location selectors.

## Mobile behavior

- Replace horizontal tables with cards or lists.
- Use full-height sheets, large touch targets, camera-first photo controls, and sticky primary confirmation actions.
- Do not require hover and do not hide handling restrictions behind secondary navigation.

## Migration and rollback

- Detect the prior unversioned seed state and create the v1 IndexedDB database once.
- Never overwrite an existing local database without a successful backup.
- On migration failure, leave the prior state readable and show a recoverable error with export instructions.
- Rollback restores the last valid backup archive and repository schema version.

## Out of scope

Shipment receiving, batch movement, outbound grouping, authentication, Supabase, QR codes, maps, OCR, and automated label recognition.

## Test plan

- Unit-test package labels, lot-derived totals, status separation, 14-day verification calculations, search ranking/match explanations, and location formatting.
- Contract-test repository seed, upgrade, transaction, photo, export, and import behavior.
- Test add, confirm, partial, not-found, removal, issue, and location-change use cases, including failed transactions.
- Add desktop/mobile Playwright coverage for project lookup and every primary action.
- Run axe checks and keyboard-only flows for search, sheets/dialogs, position selection, and photo viewing.

## Acceptance criteria

- A user can answer what is on the yard and where it is without opening several storage locations.
- Lots, not aggregate pallet/box fields, are the source of truth.
- All mutations require an operator name and appear in append-only activity.
- Search covers official names, aliases, field labels, PO, job number, materials, and locations.
- Data and photos survive reload, backup/export, and import.
- The seven-Conex model and existing design language remain intact.
