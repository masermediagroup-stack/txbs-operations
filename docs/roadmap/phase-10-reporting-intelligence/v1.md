# Phase 10 — Reporting and Operations Intelligence

> **Historical version.** Current Operator/Tech access and all-sites reporting behavior are documented in the roadmap index and current system handbook.

- Version: v1
- Status: Planned
- Depends on: Phase 7 production data; Phase 9 only for map drill-through
- Blocks: None in this roadmap

Phase 6's [temporary shared-environment plan](../phase-06-supabase-authentication/temporary-validation-plan-v1.md) must preserve permission-aware source records, UTC timestamps, unknown values, and complete audit history. Reporting views and exports remain Phase 10 work; later views must use `security_invoker` behavior so site RLS remains effective.

## Objective

Turn trusted operational records into actionable yard and management reporting without decorative dashboards, fake trends, invented capacity, or opaque calculations.

## Real-world workflow

1. Open Reports and select authorized site(s), date range, project, material, location, or issue filters.
2. Review verification work, aging material, outdoor exposure, receiving, issues, readiness/outbound, storage contents, or audit history.
3. Drill from every result to the underlying project, lot, receipt, movement, outbound batch, issue, or location.
4. Managers and Administrators export the filtered records when operational follow-up requires it.

## Domain and public interfaces

- Add typed read models for material age, verification due/overdue, outdoor exposure, location contents, receiving activity, issue trends, readiness, outbound history, and audit history.
- Calculate verification overdue from the locked 14-day threshold.
- Treat unknown values distinctly from zero and preserve source timestamps/timezones.
- Every aggregate exposes stable drill-through identifiers and a documented formula/version.

## Data and services

- Implement permission-aware SQL views or query functions with supporting indexes and `security_invoker`/RLS-safe behavior.
- Derive reports from operational records and current-lot projections; do not maintain duplicate manually editable totals.
- Use materialized views only after measured production-like query evidence and define refresh behavior before adoption.
- Generate CSV from the same filtered read model shown on screen, with explicit columns, UTC/locale-safe dates, and unknown values preserved.

## UI requirements

- Activate the existing `/reports` route with report categories, site/date/project filters, accessible summaries, tables, restrained charts, drill-through links, empty states, and CSV export.
- Use charts only for meaningful time series or distributions; every chart has an equivalent table or textual summary.
- Operators see assigned-site operational reports. Managers and Administrators also receive CSV export and audit-history access.

## Desktop behavior

- Use dense sortable tables, persistent filters, comparison only when periods are explicitly selected, and direct evidence links.
- Preserve tabular numerals and the current compact visual hierarchy.

## Mobile behavior

- Prioritize verification, exposure, issue, and readiness worklists over broad dashboards.
- Use filter sheets, stacked summaries, non-horizontal result lists, and direct operational drill-through.

## Migration and rollback

- Reporting migrations add views/functions/indexes without mutating source records.
- Version formulas and view definitions so results can be reproduced after change.
- Rollback removes or reverts read models while leaving operational tables untouched.

## Out of scope

Predictive AI, financial forecasting, executive vanity metrics, scheduled email reports, weather analytics, unverified capacity utilization, fabricated benchmarks, and automatic recommendations without explainable rules.

## Test plan

- Verify every formula against fixed fixtures, including no data, unknown dates/quantities, partial lots, reversals, daylight-saving/timezone boundaries, and multiple sites.
- Test role/site filtering at application and RLS levels.
- Verify CSV rows, filters, dates, unknown values, and totals exactly match the visible read model.
- Test drill-through, large production-like datasets, query plans/targets, mobile worklists, keyboard navigation, and accessible chart alternatives.

## Acceptance criteria

- Every metric is documented, reproducible, permission-aware, and linked to its source records.
- No report displays capacity percentages or trends without real supporting data.
- Unknown is never displayed or exported as zero.
- Operators receive useful assigned-site worklists; Managers/Administrators can export and audit.
- Production-like query performance targets are measured and recorded before acceptance.
