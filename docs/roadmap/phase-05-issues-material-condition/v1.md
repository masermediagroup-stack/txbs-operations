# Phase 5 — Issues and Material Condition

- Version: v1
- Status: Planned
- Depends on: Phase 4
- Blocks: Phase 6

## Objective

Replace the hard-coded Issues surface with durable operational exceptions that can be recorded, assigned, discussed, resolved, dismissed, and reopened without losing their history.

## Real-world workflow

1. Record an issue manually or open one created by Receiving, verification, movement, or outbound.
2. Confirm its type, priority, site, linked project/lot/receipt/location, condition evidence, and blocking impact.
3. Assign it by name, add comments/photos, and perform operational follow-up.
4. Resolve with a required resolution note, dismiss with a reason, or reopen when the problem returns.
5. Review all transitions in the issue and global activity histories.

## Domain and public interfaces

- Expand `Issue` with Missing Material, Damaged Material, Wrong Project, Wrong Quantity, Unknown Shipment, Weather Exposure, Access Blocked, and Custom types.
- Add Low, Normal, High, and Critical priorities; Open, In Progress, Resolved, Dismissed states; blocking flag; assignee name; linked-entity references; comments; resolution; and immutable transitions.
- Add `IssueComment` and `IssueTransition` with actor name, optional future user ID, timestamp, and optional media.
- Keep condition status on the lot; issues explain and track exceptions rather than replacing current condition.

## Data and services

- Add issue list/detail, create, assign, comment, transition, and link-resolution ports.
- Route all automatic issue creation through idempotent use cases so retrying a receipt or verification does not duplicate issues.
- Resolving an Unknown Shipment may link its receipt to a project but cannot rewrite the original receipt identity evidence.
- Blocking issues participate in Phase 4 readiness calculations.

## UI requirements

- Replace the current hard-coded issue array and make `/inventory/issues` repository-backed.
- Add filtering by state, type, priority, site, project, assignee, and age.
- Add issue detail history and reusable Record Issue entry points from project, lot, location, receipt, movement, and outbound views.
- Use text and icons rather than color alone for priority and state.

## Desktop behavior

- Use a dense issue list with persistent filters and a detail panel/page for assignment, discussion, evidence, and resolution.
- Preserve drill-through to every linked operational record.

## Mobile behavior

- Emphasize Record Issue, camera capture, priority, handling risk, location, and quick assignment/follow-up.
- Use large controls, full-height sheets, and a chronological conversation/history view.

## Migration and rollback

- Migrate foundation issues into the expanded schema with their current type/state and preserved activity.
- Convert current hard-coded examples only when they are explicitly retained as demo seed records; do not treat UI literals as production facts.
- Completed transitions are append-only. Rollback leaves issues readable and disables unsupported transitions.

## Out of scope

Email, Teams or SMS notifications, SLA automation, insurance claims, vendor disputes, procurement tasks, and AI damage analysis.

## Test plan

- Cover every type, priority and transition; automatic creation; duplicate prevention; assignment; comments; media; resolution/dismiss/reopen; and linked-entity navigation.
- Test unknown receipt resolution and readiness blocking/unblocking.
- Verify age calculations, filters, append-only history, desktop/mobile flows, and accessibility.

## Acceptance criteria

- Every operational exception is durable, traceable, and linked to the affected work.
- Automatic retries never create duplicate issues.
- Resolution never erases the original condition or evidence.
- Project readiness responds correctly to blocking issue state.

## Final report requirements

Use the [shared final report](../README.md#shared-final-report), including hard-coded-data removal, transition coverage, duplicate prevention, readiness integration, and confirmation that Phase 6 was not started.
