## Behavior interfaces to preserve or extend

- **Inventory command → transaction → authorized refreshed records:** `/api/inventory/commands/v1` parses the command envelope, verifies evidence, calls the inventory RPC and maps constraint/conflict/authorization errors. Reuse this design for Receiving, movement, reservation and departure extensions. Preserve command IDs, expected versions, atomic validation, evidence consumption, and source/result identities. Commercial feature-owned commands should remain separate from Tech field commands; new tables need explicit policies and server checks. [Route](../../src/app/api/inventory/commands/v1/route.ts#L14), [shared command schemas](../../src/features/inventory/domain/shared-command.ts#L126), [command receipts](../../supabase/migrations/20260810192506_phase_06_shared_inventory_foundation.sql#L557).
- **Field commands and snapshot:** `/api/field-work/commands/v1` and `execute_field_work_command_v1` provide current assignment/installation behavior. Extend read snapshots with eligible arrival/handoff quantities and actual crew evidence rather than repurposing carrier/driver notes or project stage. Existing assignment start/cancel/reassign/history is reusable. [Field route](../../src/app/api/field-work/commands/v1/route.ts#L14), [schemas](../../src/features/field-work/domain/field-work.ts#L105), [remote interface](../../src/features/field-work/services/remote-field-work-service.ts#L27).
- **Evidence transfer and attestation:** reuse stable upload identity, checksum matching, lost-response reconciliation, no-upsert writes, trusted attestation, and authorized short-lived download. Introduce dedicated document metadata/version/link interfaces and format policy; do not merely relax image acceptance, reuse broad storage access, or represent all documents as PhotoRecords. Existing verifier downloads whole bytes into memory, which needs a deliberate document-size/verification design before large workbooks/PDFs are allowed. [Verifier](../../src/features/inventory/server/verify-evidence.ts#L18), [upload](../../src/features/inventory/services/evidence-upload.ts#L30), [immutable policies](../../supabase/migrations/20260908140558_stabilization_access_and_evidence.sql#L16).
- **Account-scoped queue → replay → conflict/recovery:** extend enumerated commands, payload mapping, created-entity reconciliation, queue projections and authorized cache together. A new UI button alone does not make a workflow offline-safe. Preserve original actor/environment ownership, dependencies, expected versions, evidence recovery and human conflict decisions. Approvals, issuance, release and cost changes remain online-only. [Queue schema](../../src/features/mobile/domain/mobile-sync.ts#L6), [replay guard](../../src/features/mobile/domain/replay-guard.ts#L5), [persistence tests](../../tests/offline-persistence.test.ts#L14).

## Migration, access and offline risks

1. **Preserve historical quantity semantics.** Do not reinterpret existing package counts as product pieces or convert unknown to zero. Add product UOM/count and Handling Unit content relationships without changing original evidence. General stock is a concrete schema incompatibility: `material_lots.project_id` and `group_id` are non-null and MaterialGroup is project-specific. Allocation/split design must support unallocated stock without inventing a customer project. Repack/split/move/depart/arrival/install must conserve quantities at the proper UOM and retain physical identities. [Lot constraints](../../supabase/migrations/20260810192506_phase_06_shared_inventory_foundation.sql#L199), [domain](../../src/features/inventory/domain/inventory.ts#L41), [DEC-10](../../TODO.md#L166).
2. **Keep jobs independent of storage Sites.** Canonicalize full string job numbers and approved aliases before duplicate elimination or unique constraints. Do not infer suffixes or merge project UUIDs automatically. A Site-aware physical command may need source Site independent of project ownership; old projections/snapshot types and RLS must remain compatible during expansion. [Job SQL](../../supabase/migrations/20260810192506_phase_06_shared_inventory_foundation.sql#L142), [B-05/B-10](../../TODO.md#L85), [P-15](../../TODO.md#L117).
3. **Issued order, approval evidence and release are distinct facts.** Support early issued/held PO without falsely asserting submittal approval. Release must reference eligible line/package and document revision; superseded approval/changed PO/partial approval must not silently unlock unrelated quantities. Cross-job PO allocations need exact quantity/cost reconciliation while preserving immutable issued revisions and the sequential base-number namespace. These are new commercial rules, not an extension of project stage. [P-12/P-18](../../TODO.md#L114), [DEC-11](../../TODO.md#L167), [project-stage type](../../src/features/inventory/domain/inventory.ts#L6).
4. **Separate commercial document authorization from inventory visibility.** Current Tech read policies authorize inventory and outbound at active Sites via `has_tech_read_access`, which is broader than assignment-specific field snapshots. New supplier/cost/approval/invoice documents must not inherit this predicate. Verify Route Handler, RPC, Data API, metadata and object/download boundaries, including direct storage access and guessed IDs. Role checks in a page are insufficient. [Tech policy](../../supabase/migrations/20260818130000_tech_read_only_inventory_scope.sql#L34), [field snapshot filter](../../supabase/migrations/20260819120000_field_work_installation.sql#L166), [active-account restriction](../../supabase/migrations/20260908140558_stabilization_access_and_evidence.sql#L2).
5. **QR identity grants no authority.** Opaque URL lookup must be authenticated and resolve only current permitted record/label state. Manual lookup and scan must share business eligibility and confirmation. Label retirement/split/repack must preserve a useful historical resolution without silently applying an action to an old quantity. Another device sees committed cloud facts only; pending offline actions remain clearly pending. [Q-02](../../TODO.md#L140), [command role boundary](../../src/app/api/inventory/commands/v1/route.ts#L15), [field actor guard](../../src/app/api/field-work/commands/v1/route.ts#L15).
6. **Deep links are not offline page caching.** The worker fetches navigations and falls back to a public offline page; it does not cache authenticated HTML. Offline navigation guard protects a currently open workflow, not arbitrary first-time QR deep links. Offline scan behavior requires a deliberate prepared resolver/context and scoped records; cached IDs must not bypass expiry/role/assignment changes on replay. Retain existing session/replay hold safeguards. [Worker](../../public/sw.js#L38), [replay guard](../../src/features/mobile/domain/replay-guard.ts#L5), [session hold](../../src/app/api/auth/session/route.ts#L8).
7. **Documents are one-way system-owned copies.** Controlled Operator upload starts the cloud workflow; the server cannot use a laptop drive mapping as a cloud source connector. Record private provenance and immutable document versions; corrections produce new versions and issued outputs retain revision identity. Generic Word/Excel editing remains a separate decision. Database backup is not object-byte restore, and original sources get no writeback. [Source boundary](../../AGENTS.md#L29), [CLOUD-01](../../TODO.md#L128), [DEC-09](../../TODO.md#L165).
8. **Schema evolution spans database, snapshots and retained queues.** Use additive migrations and explicit compatibility for old cached snapshots/queued payloads; preserve historical IDs and provenance. Do not rewrite applied migrations or map old queued quantities into new product semantics. The migration harness has historical demo-data prerequisites and a scaffolded auth/storage catalog: successful local migration tests alone do not prove clean hosted baseline or actual object transport. [Snapshot version](../../src/features/inventory/domain/inventory.ts#L3), [queue version](../../src/features/mobile/domain/mobile-sync.ts#L3), [test harness](../../tests/helpers/database.ts#L6).

## Dependency recommendations and decisions still needed

These are recommendations against the current task graph, not new priority/status assignments. Preserve `A-10` → stabilization requirements and real-data production gates. Finish `SRC-01` before final WF-02 signoff; then use WF-03 to settle behavior and interfaces before implementation tickets. [TODO gates](../../TODO.md#L9), [WF-02/WF-03](../../TODO.md#L36).

- Physical foundations: **B-05 → B-10 → P-19**, alongside **P-15** canonical job/destination identity. Complete explicit source Site and receipt lineage before product/handling-unit import. Shared-stock allocation design belongs in P-19, not a fabricated job record.
- Commercial foundations: **CLOUD-01 + P-15/P-19 → P-11/P-18 → P-12 → P-13**. P-18 implements approval/hold/release capability; it does not require every early PO to be fully released before issuance. Keep PO and release state independent.
- Custody and installation: **P-13/P-15/P-19 → P-16 → P-17**. Arrival sets eligible install quantities; direct delivery uses real receipt/arrival lineage without invented departure. Retain B-11 field acceptance as a dependency.
- Financial/automation extensions: **P-12/P-13/CLOUD-01 → P-20**; **B-08 + commercial/document foundations → CLOUD-02**. Invoice reconciliation/export does not execute payments. Reminders do not approve or release business work.
- QR: **P-19 → Q-01**, then existing Q-02 document/handoff/installation gates. Manual workflows and stable Handling Unit IDs should work before printer stock/hardware selection. Validate the phone/cloud confirmation path before optional scanner integration.
- Decisions to settle through WF-03: product UOM precision/conversion rules; content cardinality and repack lineage; allocation/return correction behavior; crew recorder/participant authority; direct-delivery custody semantics; document preview/size/retention/restore scope; private provenance/search boundaries; offline resolver UX and conflict behavior. Where a consequential choice conflicts with an accepted ADR, record the explicit tradeoff and proposed replacement rather than quietly changing its invariant.
